# `ref/` — VR gene annotation and genomic cluster reference (GRCm38)

Reference layer for the VNO receptor RNA-seq project. Downstream QC, marker, and
quantification tracks **join against these tables**; they do not re-derive coordinates.

Generated by `bin/build_vr_reference.py` v1.0.0. Re-runnable:

```bash
module load python/3.11.4
python bin/build_vr_reference.py \
    --config config/project.yaml \
    --outdir ref
```

## Matching rule (family membership)

Case-sensitive, anchored regex on `gene_name`:

- `^Vmn1r` → `family = V1R`
- `^Vmn2r` → `family = V2R`

This deliberately catches pseudogene names (`Vmn1r-ps150`) and all numeric variants.
Nothing is excluded by biotype at the matching step.

## Pseudogene criteria (auditable)

`is_pseudogene = 1` if **either** criterion fires; the column `pseudogene_criterion`
records which one, so the rule can be re-litigated without re-parsing:

| criterion | meaning | n genes |
|---|---|---|
| `biotype+name` | `gene_biotype` contains `pseudogene` **and** name contains `-ps` | 209 |
| `biotype` | biotype only — name does not say `-ps` | 2 |
| `name` | name says `-ps` but biotype is not a pseudogene biotype | 3 |
| `none` | functional | 327 |

The 5 genes where the two criteria disagree are the ones to watch: they are counted as
pseudogenes here, but a downstream track that cares about the distinction should read
`pseudogene_criterion` rather than trusting `is_pseudogene` alone.

## Clustering rule

Single-linkage on genomic proximity, **within family**:

1. Sort VR genes by chromosome, then start position.
2. Walk the sorted list; cut a new cluster whenever
   `next.start - running_max_end > cluster_max_gap_bp` (200,000).
3. V1R and V2R are clustered **independently** — a V1R gene and a V2R gene 50 kb apart
   never share a cluster. This matters on chr7 and chr17 where the two families interleave.
4. `cluster_id` = `<family>_chr<chrom>_cl<NNN>`, ordinal zero-padded to 3 digits and
   numbered sequentially along the genome **within family**.

Result: **24 V1R clusters** (7 singletons, largest 64 genes) and **37 V2R clusters**
(18 singletons, largest 36 genes).

Major V1R clusters land on chromosomes **6, 7, 13, 17** exactly as the briefing expects
(chr7 = 143 genes / 10 clusters, chr6 = 77 / 5, chr13 = 64 / 1, chr17 = 24 / 1). These
four chromosomes carry 308 of 319 V1R genes.

### Second tier: `supercluster_id`

Each gene and cluster also carries a `supercluster_id` (`<family>_chr<chrom>_sc<NNN>`)
from a coarser 800 kb pass, giving **19 V1R and 26 V2R superclusters** across all assembly
units — or **18 V1R** on the primary assembly alone, since one supercluster
(`V1R_chrGL456219.1_sc019`) is a lone gene on an unplaced scaffold. This is **advisory
context, not the aggregation unit** — see the Dietschi cross-check below for why it
exists. Aggregate on `cluster_id`; use `supercluster_id` only when comparing against
published cluster-level numbers.

## Cluster ID mapping to prior project labels

Prior findings in this project use the labels *"V1R chr7 cluster 039 (Vmn1r91-166 region,
60 paralogs)"* and *"V1R chr6 cl029 (Vmn1r32-39)"*. **The derived ordinals do not
reproduce those numbers**, and no numbering scheme tested does (per-family and
genome-global orderings were both swept across thresholds from 50 kb to 300 kb). The
*membership* reproduces exactly; only the ordinal differs. Mapping:

| prior label | derived ID(s) | membership |
|---|---|---|
| V1R chr6 cl029 (Vmn1r32-39) | **`V1R_chr6_cl008`** | exact match — `Vmn1r32,33,34,35,36,37,-ps24,38,39` (9 genes) |
| V1R chr7 cluster 039 (Vmn1r91-166, 60 paralogs) | **`V1R_chr7_cl015` + `V1R_chr7_cl016`** | union is exactly 60 genes (49 functional, 11 pseudogenes), spanning chr7:20,101,158-23,251,682 |

The chr7 case is substantive, not cosmetic: at the 200 kb rule the Vmn1r91–166 region
splits into two clusters because `Vmn1r132` and `Vmn1r135` are **217,366 bp** apart —
just 17 kb over the threshold. The prior "60 paralogs" label corresponds to merging them,
which happens at any threshold ≥ 218 kb. Both are captured: the 200 kb tier keeps them
separate (`cl015`, `cl016`) and the 800 kb supercluster tier reunites them.

**Downstream tracks must use the derived IDs and treat the prior labels as aliases**, not
renumber to match. The ordinals `cl039`/`cl029` appear to come from a different
(likely genome-global, finer-threshold) enumeration that was not reproducible from this
annotation; recording the mapping is preferred to fudging the scheme.

## Dietschi et al. 2022 cross-check

Dietschi et al., *Sci Adv* 8(46):eabn7450, doi `10.1126/sciadv.abn7450`.

**(a) Cluster aggregation rationale — confirmed, and stronger than expected.** The paper's
central finding is that clustering is functionally required, not merely a genomic
accident: cluster identity predicts both transcript level and probability of choice
(ANOVA on functional genes of mixed clusters, P < 2×10⁻¹⁶; effect on VSN abundance,
P = 0.000232). The cluster is therefore the biologically meaningful unit, which is the
justification for reporting cluster-level VR calls as the reliable tier.

**(b) Pseudogene bleed — the paper's effect is regulatory, not a mapping artifact.
Read this carefully before building the bleed flag.** Dietschi et al. report that V1r
pseudogenes are more likely to be expressed when located inside a functional cluster than
when isolated. Their measurement: compare mean expression of pseudogenes inside "mixed
clusters" (functional genes + pseudogenes) against pseudogenes outside them, by Wilcoxon.
Critically, **the mouse comparison was not significant** (141 Ψ in mixed clusters vs 16
outside, W = 1214, P = 0.5704); only the rat reached significance (102 vs 16, W = 1113,
P = 0.002987). They also confirm pseudogene transcription is very low overall relative to
intact genes (W = 33822, P < 2.2×10⁻¹⁶).

Two consequences for the bleed flag a later track builds:

1. Their claim is about *genuine cluster-associated transcriptional activity* from shared
   regulatory elements — a real biological signal. Our concern is different: **EM
   redistribution of multi-mapping reads onto pseudogene paralogs**. These are separate
   mechanisms that produce the same observation. A pseudogene with apparent expression
   inside a functional cluster is ambiguous between them, and the flag should say so
   rather than asserting either.
2. Because the mouse effect was **not** statistically significant, do not calibrate a
   mouse pseudogene-expression expectation from this paper. Use it as motivation for the
   flag, not as a quantitative prior.

**(c) Cluster definition — materially different from the 200 kb rule.** Dietschi et al.
do not use a fixed base-pair threshold. They derive an "aggregation threshold" per species
from the distribution of intergenic distances between neighbouring consecutive V1r
sequences on each chromosome (intact or pseudogenic CDSs), and genes that cannot be
clustered are called singletons. For mouse they report **18 V1r clusters, largest 105
members, mean 37, and ~12 singletons of which most are pseudogenic**.

Our 200 kb rule gives **24 V1R clusters, largest 64, 7 singletons** — a finer partition.
Reproducing their published mouse count of 18 requires a threshold of ~**800 kb** on this
annotation, **counted on the primary assembly**: at 800 kb this annotation yields 19 V1R
superclusters across all assembly units and 18 restricted to chr 1–19/X/Y, the extra one
being a lone gene on unplaced scaffold `GL456219.1`. The primary-assembly count is the
basis comparable to a published karyotype-level figure. Do not quote "18" without that
qualifier — the threshold sweep in `vr_gtf_parse_report.txt` prints both columns (`n` for
all assembly units, `nP` for primary only) for every threshold tested. Note that 1000 kb
gives 18 all-units but only 17 primary-only, so it does *not* match on the comparable
basis. Their larger maximum cluster (105 vs our 78 at 800 kb) is expected: they used
Ensembl v86 plus a *custom annotation with de novo–identified V1r pseudogenes added*, so
their repertoire is larger than what this GTF contains.

Checking the 200 kb choice against the data directly (see the threshold sweep and gap
percentiles in `vr_gtf_parse_report.txt`): V1R intergenic gaps are strongly unimodal
around 18–32 kb (median 25.3 kb, q75 40.2 kb), and the distribution thins out gradually
rather than showing a clean valley near 200 kb. A kernel-density minimum on log₁₀ gap sits
near 2 Mb, far above 200 kb. Ten V1R gaps fall in the ambiguous 150–500 kb zone —
including the 217,366 bp gap that splits the Vmn1r91–166 region. **200 kb cuts through a
continuum, not at a natural break.**

**Recommendation (the rule was NOT changed unilaterally).** Keep `cluster_max_gap_bp =
200000` as the primary aggregation unit: it is conservative in the direction that matters
for this project. A finer partition means paralogs that are 85–95% identical and mutually
unresolvable by 75 bp reads still land in the same cluster (all within-cluster gaps are
≤ 200 kb, well inside the local-duplicate scale), while genuinely distant paralogs are not
silently merged — so a cluster-level call remains a defensible statement. The cost is that
cluster counts are **not** directly comparable to Dietschi's published numbers. The
`supercluster_id` column (800 kb) exists to make that comparison possible without
re-clustering. If a future analysis needs to reproduce the paper's cluster identities,
aggregate on `supercluster_id`; for EM-artifact reasoning, stay on `cluster_id`.

## Caveats for downstream tracks

- **Join on `gene_id`, not `gene_name`** — `Vmn1r-ps5` and `Vmn2r118` each map to two
  distinct gene_ids.
- **Filter to `is_primary_assembly = 1`** (538 genes) when joining to quant tables; the
  other 3 genes cannot appear in Salmon output.
- **Per-gene VR counts within a cluster are not trustworthy** (85–95% paralog identity vs
  75 bp reads). Aggregate on `cluster_id`. Near-equal fractions among cluster members
  (e.g. 33/33/33) is the signature of one expressed paralog with EM-split reads.
- **`n_functional` vs `n_pseudogenes` per cluster** is provided so a track can compute the
  functional-only cluster total and compare it to the all-member total; a large gap between
  them is where pseudogene bleed would show up.
- Singleton clusters (7 V1R, 18 V2R) have no within-cluster ambiguity, so a call there is
  better-determined than a call inside a 64-gene cluster — but they are also enriched for
  pseudogenes, per Dietschi et al. Fig. 1F.
- This layer contains **no expression data by design**. QC/markers and quantification are
  owned by other tracks.
